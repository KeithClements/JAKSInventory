✨ Implementation Plan

Single shared widget (ProductWorkbenchDialog) drives both flows. A mode argument "new" | "edit" decides accents, side-rail content & footer buttons. All section bodies are identical Qt widgets across modes — only data, placeholders & required-field highlighting differ.

What's shared

  • Window frame & titlebar
  • 3-column workbench grid (rail · canvas · meta)
  • Left rail with 13 section tabs + filter + progress mini
  • Always-visible cards: Basic + Core Charge
  • Section cards: Platform, Supplier, Warranty, Pricing, Inventory, Notes, Shipping, Cross-refs, Suggested Sells, Images, Shopify
  • Tiered pricing block (toolbar · price-floor row · tiers table · margin warning)
  • Sticky footer bar (status + dirty flag + actions)
  • Keyboard shortcuts (Ctrl+S save, Ctrl+1-9 jump section, Esc cancel)

What's different

  • Header accent: New = teal · Edit = olive
  • AI bar: prominent under header in New · compact buttons in header for Edit
  • Mode chip + window title swap (Add Product vs Edit Product: SKU)
  • SKU field: placeholder in New · monospaced value in Edit
  • Required-field chips light up in New, hide in Edit (already-saved data is valid)
  • Meta rail content: New shows Completion + Will-be-created + empty-state. Edit shows Quick Stats + Activity + AI Insights.
  • Footer buttons: New = Cancel · Save Draft · Save & Add Another · Save & Duplicate · Save & Close. Edit = Discard · Duplicate · Delete · Save Changes
  • Core Charge card: collapsed in New (toggle only), expanded with both panes in Edit if active
  • Pricing margin column: blank "—" in New until cost & price set · color-coded live in Edit

Tiered-pricing component spec

  1. Pricing toolbar — segmented mode (Tiered/Flat/Formula), live KPIs (cost basis, target margin, 90d cost trend), and helper buttons (Reset to vendor · Copy from similar · History).
  2. Price-floor row — 4-column grid: Avg/Std Cost, Last Cost, List Price, MAP/Floor.
  3. Tiers table — columns: Tier · Min Qty · Price · Discount · Margin · Source · Actions. Inline-editable cells; Margin auto-computed from Cost. Source chips = manual / vendor sheet / ✨ AI suggested / ⚖ MAP floor.
  4. Row actions — lock (freeze on bulk recompute), remove. Lock state persists in DB.
  5. Add tier CTA row creates a new tier with auto-named label (Retail → Dealer → Fleet → Wholesale → Distributor → Custom 1 …).
  6. Margin warning bar — red if any tier dips below MAP/Floor; green if all healthy.
  7. AI hooks — "✨ Suggest tiers" computes 3 tiers from target margin; "📊 Competitor scan" calls existing scrape pipeline.

Implementation steps (proposed order)

  1. Build ProductWorkbenchDialog(QDialog) skeleton with mode param: titlebar, header strip (color-aware), 3-col grid, sticky footer. Replaces both add_product_dialog.py & edit_product_dialog.py.
  2. Port the 13 section widgets from edit_product_dialog.py into independent QWidget subclasses so they can be reused unchanged. Wire them into a QStackedWidget or scrollable column.
  3. Build the section rail (filter + grouped tabs + progress mini). Tabs drive scroll-to-section + active highlight. Required/health badges from per-section validate() hooks.
  4. Build the Always-on Basic card + collapsible Core Charge card at the top of the canvas (shared widget).
  5. Build the new Tiered Pricing widget (PricingTiersTable) with the spec above. Replace the legacy flat-price pricing section in both flows.
  6. Build the Meta Rail as two swappable layouts: NewProductMetaPanel (completion + AI suggestions + will-be-created) and EditProductMetaPanel (quick stats + activity + AI insights + sparkline).
  7. Wire the AI command bar (visible in New only) to the existing scrape/OCR/cross-ref pipelines.
  8. Migration: route the existing "Add New Product" + "Edit Product" call sites in products_screen.py to the new dialog with the appropriate mode. Keep the legacy dialogs behind a feature flag for one release.
  9. Add keyboard nav (Ctrl+S, Ctrl+1-9 jump, Esc cancel, Alt+arrow tier navigation).
  10. QA passes: dark-theme parity, focus rings, tab order, scrollbar consistency, and tiered-pricing math edge cases (zero cost, MAP overrides, locked rows).

Approve this plan and I'll start with step 1 (skeleton + shared frame) — that's the biggest win and is independent enough to ship without breaking existing flows.
